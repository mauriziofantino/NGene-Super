GPS acquisition in NGene Evo

Implementation review against the bundled original NGene source · 19 October 2026 · GPS L1 C/A only

Finding: A complete cross-ambiguity surface is evidence that the search ran, not that a satellite was detected. The current implementation acquires a deterministic complex-I/Q signal at approximately 40 dB-Hz with eight noncoherent sums in an automated test. It has not been validated against the user's live RF capture. No unique cause of the reported failed live acquisition can be established from the screenshot alone.

1. Signal path and I/Q convention

SDR or I/Q file → native complex pairs → optional conditioner → kernel windows
             → acquisition channel (one PRN) → 1 ms private frame
             → remove frame I/Q means → wipe off residual carrier
             → compress complex samples → FFT correlation → detection/refinement

The original NGene frontend delivered real intermediate-frequency samples. Its coarse acquisition called GenerateCarrier and CarrierComplexWipeOff to create in-phase and quadrature streams before SampleCompression. NGene Evo's frontend already delivers simultaneous I and Q values. The acquisition module does not split a real stream or repeat the analog quadrature demodulation. It reads each native pair using NgIqComponent: signed CI8 directly, unsigned CU8 recentered by subtracting 128, or signed SC16/Q11 without truncating to 8 bits.

Acquisition receives the post-conditioner kernel stream. With bypass, those are the frontend's original samples. With dc_iir, the continuous DC estimate has already been subtracted. In either case, the acquisition correlator also subtracts the mean I and Q of its own 1 ms frame before carrier mixing. This local centering does not alter the shared receiver stream.

The frontend's configured signal centre minus its hardware tuning frequency is digitalIfHz. A Doppler hypothesis fD produces an NCO at digitalIfHz + fD. For input x[n] = I[n] + jQ[n], the NCO computes y[n] = (x[n] − mean) exp(−j2π(digitalIfHz + fD)n/Fs). If the hardware is tuned to nominal GPS L1, digital IF is zero: the NCO still removes the hypothesized residual Doppler. The code NCO is independent of the carrier NCO.

2. Coarse acquisition: what was preserved and changed

OperationOriginal NGeneNGene Evo
Input and carrierReal IF; generate cosine/sine, then form I/Q.Native complex pairs; multiply by conjugate residual carrier NCO.
Coherent periodGPS C/A code period, normally 1 ms.One private 1 ms frame, assembled across arbitrary kernel windows.

For sample rate Fs, a code period contains approximately Fs/1000 complex pairs. The configured FFT size is reduced to the largest allowed power of two at or below that count. At 2.4 Msps, a requested 4096-point FFT therefore becomes 2048 points. The compression partitions the 1 ms input into contiguous groups; each FFT input is the complex sum of its group's carrier-wiped samples. Supplementary shifted origins cover fractional code offsets that a single compression grid misses. The generated local code is summed over the same group boundaries.

For each Doppler and shift, the correlator produces one power for every compressed code lag. Powers from M separate 1 ms frames are summed noncoherently; complex amplitudes are not added across those frames. The current detector compares the peak against a local off-peak mean multiplied by a factor calculated from the configured per-cell false-alarm probability. This factor assumes approximately independent white-noise cells; real interference, filtering and repeated searches can violate that assumption.

3. Refinement and confirmation

When the coarse peak exceeds its threshold, the module refines Doppler around that candidate using full-rate, 1 ms prompt correlations. It then refines code delay in native sample steps. For a prompt at code phase τ, it multiplies the carrier-wiped I/Q pair by the local ±1 C/A chip and sums I and Q across the frame. The prompt power is (ΣI/N)² + (ΣQ/N)². The code rate is corrected by 1 + fD/1575.42 MHz. The carrier phase is deliberately left invalid because GPS navigation-bit polarity gives a π ambiguity.

Optional M-of-N confirmation uses later, separate frames, with 32 off-peak code shifts as its noise references. The default is 3 hits in 4 attempts. With confirmation disabled, a refined coarse detection is reported immediately; that is a weaker claim than a confirmed detection. Neither result implies tracking lock, navigation decoding or a position fix.

4. Kernel API, timing and the GUI surface

The kernel passes borrowed, immutable windows of complex pairs to acquisition channels. NgAcquisitionProcess copies only enough samples to form its next 1 ms private frame. A 5 ms window is therefore handled as five consecutive code periods; a shorter window may be joined with the next. Epoch changes or sample gaps reset partial coherent history and candidate state. Channel scheduling can process separate PRNs concurrently. The receiver starts with one noncoherent sum and raises it toward the configured maximum after PRN-list cycles; this follows the old NGene policy but can delay weak-signal detection.

The 2D/3D cross-ambiguity plot is a bounded display cache, not the full detector. It max-pools measured coarse powers into at most 64 Doppler × 64 code-delay cells. Different Doppler rows come from different milliseconds. The colors and height are normalized to the strongest displayed cell; a yellow peak is not an acquisition decision. Hiding the plot skips this pooling but does not stop the correlation required for detection. In the supplied screenshot the plot says “Complete sweep”, “2 noncoherent 1 ms periods”, and “FFT 1024 points”; it shows a nearly flat surface and a relative peak, not a threshold crossing or confirmation.

5. What the present evidence does and does not prove

The existing synthetic tests check original C/A code hashes, FFT correlation against independent calculations, code and Doppler estimates, CI8/CU8/SC16 input, DC bias, no-antenna noise, sample-chunk invariance, and optional confirmation. A new test feeds approximately 40 dB-Hz complex CU8 GPS-like signal at 3.2 Msps, with an effective 2048-point FFT, quarter-chip supplementary step, eight noncoherent sums, Pfa=10⁻⁹ and 3-of-4 confirmation; it passes. The synthetic model is idealized and does not reproduce analog filters, oscillator drift, multipath, interference or dropped USB samples.

For live reception, the first items to check are: (1) metric / threshold for the selected PRN after a completed sweep, and the current noncoherent-sum count; (2) sample-gap/reset counters; (3) the actual RF centre error. A ±5 kHz Doppler window covers only about ±3.17 ppm of L1 centre-frequency error even before satellite Doppler is allowed for. A tuner offset of several ppm can put every satellite outside the configured search. Gain calibration checks ADC distribution; it does not calibrate L1 frequency or prove antenna reception. The screenshot alone provides none of these measurements, so attributing the failure to one cause would be speculation.
